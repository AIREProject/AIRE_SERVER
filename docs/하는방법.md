# 공개 서버 폴더 교체 작업서

이 문서는 개발 PC의 `AIRE_SERVER` 폴더를 통째로 들고 가서 기존
`https://api.mtvs2026.work` 서버에 반영하는 순서입니다.

서버 PC에는 Git, GitHub 로그인과 ZIP 생성이 필요하지 않습니다.

## 0. 전체 순서

```text
개발 PC의 AIRE_SERVER 폴더를 서버로 복사
→ 기존 공개 서버 정상 상태 확인
→ 기존 API 서비스 중지
→ 새 폴더의 개발용 .env/data/.venv를 사용하지 않도록 분리
→ 기존 서버의 .env, data와 Docker 설정을 새 폴더로 복사
→ 기존 배포 폴더를 백업 이름으로 변경
→ 새 폴더를 기존 배포 경로로 변경
→ dependency와 DB migration 반영
→ service/container 재시작
→ 공개 Health, Chat, Task 조회 검증
```

## 1. 반드시 지킬 규칙

새 폴더에서 실행 코드는 사용하지만 다음 값은 기존 공개 서버의 것을 유지합니다.

- `.env`: Local LLM 주소, model과 운영 설정
- `data/`: SQLite DB, Transcript, Memory와 요청 로그
- Docker volume
- `Dockerfile`, Compose 파일과 `.dockerignore`
- reverse proxy와 Cloudflare 설정
- 기존 내부 application port

개발 PC에서 가져온 `.env`, `data/companion.db`, `.venv`를 공개 서버 운영 값으로 사용하지
않습니다. `.git`은 함께 가져가도 실행에는 사용하지 않습니다.

경로나 서비스 이름을 모르면 추측하지 말고 작업을 중단합니다.

## 2. 개발 PC에서 폴더 가져가기

다음 폴더를 USB, 외장 저장장치, SFTP 또는 서버 관리자가 승인한 파일 전달 방식으로 그대로
가져갑니다.

```text
C:\workspace\Github\AI_RE\AIRE_SERVER
```

서버에는 기존 배포 폴더와 다른 이름으로 먼저 복사합니다.

Linux 서버 예시:

```text
/tmp/AIRE_SERVER_NEW
```

처음부터 기존 운영 폴더 위에 덮어쓰지 않습니다.

새 폴더에 다음 항목이 있는지 확인합니다.

```bash
new_dir="/tmp/AIRE_SERVER_NEW"

test -f "$new_dir/pyproject.toml" && echo 'pyproject OK' || echo 'pyproject missing'
test -f "$new_dir/alembic.ini" && echo 'alembic OK' || echo 'alembic missing'
test -d "$new_dir/app" && echo 'app OK' || echo 'app missing'
test -d "$new_dir/migrations" && echo 'migrations OK' || echo 'migrations missing'
```

하나라도 missing이면 진행하지 않습니다.

## 4. 현재 공개 서버 확인

작업자 PC 또는 서버에서 실행합니다.

```bash
curl -fsS https://api.mtvs2026.work/health
curl -fsS -o /dev/null -w '%{http_code}\n' https://api.mtvs2026.work/docs
```

정상 기준:

- Health HTTP `200`
- `status=ok`
- 현재 운영 서버의 `llm_provider=local`
- Swagger HTTP `200`

이미 실패하고 있다면 배포 전 장애와 배포 장애를 구분할 수 없으므로 중단합니다.

## 5. Docker인지 직접 실행인지 확인

```bash
whoami
pwd
date
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
docker compose ls
```

판정:

- API container가 보이면 Docker 절차를 사용합니다.
- Docker가 없고 systemd/Uvicorn process가 있으면 직접 실행 절차를 사용합니다.
- 어느 process가 API인지 모르겠으면 위 출력을 담당자에게 전달하고 중단합니다.

Docker Compose 프로젝트 디렉터리에서는 API service 이름을 확인합니다.

```bash
docker compose config --services
docker compose ps
```

이후 `<api-service>`를 실제 이름으로 바꿉니다. 괄호까지 입력하지 않습니다.

systemd service는 다음으로 찾습니다.

```bash
systemctl list-units --type=service | grep -Ei 'aire|mako|uvicorn'
```

## 6. 기존 배포 폴더 확인

실제 경로를 변수에 넣습니다. 아래 예시 경로를 그대로 사용하지 않습니다.

```bash
deploy_dir="/실제/AIRE_SERVER/배포/경로"
new_dir="/tmp/AIRE_SERVER_NEW"

cd "$deploy_dir"
pwd
ls -la
```

기존 설정과 DB는 내용이 아니라 존재 여부만 확인합니다.

```bash
test -f "$deploy_dir/.env" && echo '.env exists' || echo '.env missing'
test -f "$deploy_dir/data/companion.db" && echo 'database exists' || echo 'database not found here'
```

`.env missing`이면 Local LLM 설정을 잃을 수 있으므로 중단합니다.

Docker에서 DB가 폴더 안에 없다면 mount를 확인합니다.

```bash
docker inspect <실행-중인-api-container> --format '{{json .Mounts}}'
```

`data/`가 host directory인지 named volume인지 기록합니다. 구분할 수 없으면 중단합니다.

## 7. API 서비스 중지

SQLite를 안전하게 보존하기 위해 먼저 쓰기를 멈춥니다.

### Docker Compose

```bash
cd "$deploy_dir"
docker compose stop <api-service>
docker compose ps
```

### systemd

```bash
sudo systemctl stop <api-service-name>
sudo systemctl status <api-service-name> --no-pager
```

### 수동 Uvicorn

기존 Uvicorn을 실행한 terminal/session에서 `Ctrl+C`로 정상 종료합니다. 알 수 없는 process에
임의로 `kill -9`를 실행하지 않습니다.

## 8. 새 폴더의 개발용 상태 분리

개발 PC에서 같이 가져온 `.env`, `data`, `.venv`가 있으면 삭제하지 않고 이름을 바꿔
운영 경로에서 제외합니다.

```bash
if [ -f "$new_dir/.env" ]; then
  mv "$new_dir/.env" "$new_dir/.env.development-copy-not-used"
fi

if [ -d "$new_dir/data" ]; then
  mv "$new_dir/data" "$new_dir/data.development-copy-not-used"
fi

if [ -d "$new_dir/.venv" ]; then
  mv "$new_dir/.venv" "$new_dir/.venv.development-copy-not-used"
fi
```

Windows에서 만든 `.venv`는 Linux 서버에서 사용할 수 없습니다. 서버에서 `uv sync`로 다시
만듭니다.

## 9. 기존 운영 설정과 데이터 이식

기존 `.env`는 반드시 새 폴더로 복사합니다.

```bash
cp -a "$deploy_dir/.env" "$new_dir/.env"
```

기존 DB가 `deploy_dir/data`에 있는 일반 폴더 또는 bind mount라면 전체를 복사합니다.

```bash
cp -a "$deploy_dir/data" "$new_dir/data"
```

Docker named volume이면 위 `cp`를 실행하지 않습니다. 기존 Compose가 같은 named volume을 새
container에도 연결하도록 유지합니다.

기존 배포 폴더에 Docker 설정이 있다면 새 폴더로 복사합니다.

```bash
for file in Dockerfile docker-compose.yml docker-compose.yaml compose.yml compose.yaml .dockerignore; do
  if [ -f "$deploy_dir/$file" ]; then
    cp -a "$deploy_dir/$file" "$new_dir/$file"
  fi
done
```

별도 deployment script나 service 설정 파일이 기존 폴더에 있다면 담당자가 확인한 파일만
추가로 복사합니다. reverse proxy 설정이 저장소 밖에 있으면 그대로 둡니다.

이식 결과를 확인합니다.

```bash
test -f "$new_dir/.env" && echo '.env copied' || echo '.env missing'
test -f "$new_dir/data/companion.db" && echo 'database copied' || echo 'database not found here'
```

Docker named volume이면 두 번째 결과는 `database not found here`여도 됩니다. 그 대신 Compose
mount가 기존 volume을 가리키는지 확인해야 합니다.

## 10. 기존 폴더를 백업하고 새 폴더로 교체

서비스가 중지됐고 `.env`와 DB/volume 보존을 확인한 뒤에만 실행합니다.

```bash
backup_stamp="$(date +%Y%m%d-%H%M%S)"
backup_dir="${deploy_dir}_backup_${backup_stamp}"

mv "$deploy_dir" "$backup_dir"
mv "$new_dir" "$deploy_dir"

test -d "$backup_dir" && echo 'old deployment backup OK' || echo 'backup missing'
test -f "$deploy_dir/pyproject.toml" && echo 'new deployment OK' || echo 'new deployment missing'
test -f "$deploy_dir/.env" && echo '.env preserved' || echo '.env missing'
```

기존 폴더 전체가 `backup_dir`에 남아 있으므로 임의로 삭제하지 않습니다.

## 11-A. Docker Compose로 반영

Docker를 사용하는 경우에만 실행합니다.

```bash
cd "$deploy_dir"
docker compose build <api-service>
docker compose run --rm <api-service> uv run alembic upgrade head
docker compose run --rm <api-service> uv run alembic current
docker compose up -d <api-service>
docker compose ps
docker compose logs --tail 100 <api-service>
```

확인할 것:

- migration container가 기존 DB folder/volume을 사용함
- API container가 `Up` 또는 정상 상태
- 반복 restart와 traceback 없음
- reverse proxy가 바라보는 기존 internal port 유지

공개 서버 internal port를 로컬 테스트 값 `8010`으로 임의 변경하지 않습니다.

## 11-B. 직접 Uvicorn으로 반영

Docker를 사용하지 않는 경우에만 실행합니다.

```bash
cd "$deploy_dir"
uv sync --frozen
uv run alembic upgrade head
uv run alembic current
```

systemd를 사용한다면:

```bash
sudo systemctl start <api-service-name>
sudo systemctl status <api-service-name> --no-pager
```

수동 실행이 기존 운영 방식일 때만 기존 internal port로 실행합니다.

```bash
uv run uvicorn app.main:app --host 0.0.0.0 --port <기존-내부-port>
```

SSH terminal을 닫아도 유지되어야 하는 공개 서버에서는 기존 systemd, Docker 또는 process
supervisor를 사용합니다.

## 12. 공개 서버 검증

### 12.1 Health와 Swagger

```bash
curl -fsS https://api.mtvs2026.work/health
curl -fsS -o /dev/null -w '%{http_code}\n' https://api.mtvs2026.work/docs
```

Health만으로 DB와 LLM 성공을 판단하지 않습니다. Chat도 호출합니다.

### 12.2 `AIRE_GAME` Chat

```bash
request_id="deploy-game-$(date +%Y%m%d%H%M%S)"
curl -fsS -X POST 'https://api.mtvs2026.work/api/v1/chat' \
  -H 'Authorization: Bearer AIRE_GAME' \
  -H 'Content-Type: application/json' \
  -H "X-Request-ID: $request_id" \
  --data-binary "{
    \"schema_version\": 1,
    \"request_id\": \"$request_id\",
    \"session_id\": \"deploy-game-session\",
    \"save_slot_id\": \"demo-slot-1\",
    \"companion_id\": \"mako\",
    \"message_id\": \"message-$request_id\",
    \"user_message\": \"배포 확인\",
    \"surface\": \"game\",
    \"time_context\": {
      \"source\": \"GameWorld\",
      \"day\": 1,
      \"hour\": 12,
      \"period\": \"Afternoon\"
    },
    \"recent_event_ids\": [],
    \"game_context\": {},
    \"allowed_commands\": []
  }"
```

정상 기준:

- `display_text`가 비어 있지 않음
- `ai_metadata.provider=local`
- `AuthenticationUnavailable`이 나오지 않음

### 12.3 `AIRE_WEB` Chat

위 요청에서 다음 값을 바꿔 다시 호출합니다.

```text
Authorization: Bearer AIRE_WEB
surface: mobile
time_context.source: RealWorld
```

### 12.4 기존 Offline Task 조회

새 test Task를 만들지 않고 조회만 합니다.

```bash
curl -fsS \
  -H 'Authorization: Bearer AIRE_GAME' \
  'https://api.mtvs2026.work/api/v1/tasks?save_slot_id=demo-slot-1'
```

빈 `tasks` 배열도 정상입니다. HTTP 오류나 DB table 오류가 없어야 합니다.

## 13. Mobile Web 확인

Mobile Web이 API와 다른 origin이면 브라우저 CORS 설정이 필요합니다. PowerShell이나 curl
성공만으로 브라우저 성공을 대신하지 않습니다.

확인 항목:

- 모바일 브라우저에서 Chat 화면 진입
- 한 번 전송 후 MAKO 응답 표시
- 개발자 도구 Network의 `POST /api/v1/chat` 성공
- `CORS`, `OPTIONS 405`, `blocked by browser` 오류 없음

## 14. 즉시 중단할 조건

- 기존 배포 경로 또는 실행 방식을 모름
- `.env` 또는 운영 DB/volume 위치를 모름
- 서비스 중지 전 DB를 복사함
- 기존 폴더 backup을 확인하지 못함
- 새 폴더가 기존 경로를 처음부터 덮어씀
- Alembic migration 실패
- reverse proxy `502/504`
- `AuthenticationUnavailable`
- Health는 성공하지만 Chat이 DB/LLM 오류로 실패
- `ai_metadata.provider`가 기존 `local`에서 의도치 않게 `mock`으로 변경

오류가 나면 같은 명령을 반복하거나 backup 폴더를 삭제하지 않습니다. 다음 출력을 담당자에게
전달합니다.

```bash
docker compose ps
docker compose logs --tail 200 <api-service>
uv run alembic current
curl -i https://api.mtvs2026.work/health
```

`.env` 내용과 인증 header는 전달하지 않습니다.
