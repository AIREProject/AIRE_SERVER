# 개발 기록 작성 규칙

이 디렉터리에는 개발이 완료된 기능의 구현 범위와 검증 결과를 기록한다.

## 저장 위치와 파일명

- 파일명은 `YYMMDDHHmm_<feature>-development-log.md` 형식을 사용한다.
- 제목은 `YYMMDDHHmm <기능명> 개발 기록` 형식을 사용하고, `기록일`은 `YYYY-MM-DD HH:mm` 형식을 사용한다.
- 시각은 저장소 기준 시간대인 KST(`+09:00`)로 작성한다.
- 시간이 명시되지 않은 기존 기록을 보완할 때는 해당 구현을 반영한 Git 커밋 시각을 사용한다.
- 개발 완료 기록만 이 디렉터리에 둔다.
- 진행 중인 계획이나 후속 작업 목록은 `docs/` 루트에 둔다.
- 기존 활성 명세를 복사하지 말고, 결정 사항과 구현 결과만 요약한다.

## 기본 형식

```markdown
# YYMMDDHHmm <기능명> 개발 기록

- 기록일: YYYY-MM-DD HH:mm
- 기록 유형: 기능 개발 완료 기록
- 변경 범위: <이번 작업에서 변경한 범위>
- 구현 기준: `<commit> <commit message>`
- API/스키마 버전: `<해당하는 경우>`
- 후속 범위: <남은 작업 또는 없음>

## 1. 완료 상태 요약

## 2. 구현 범위와 주요 결정

## 3. 변경 파일

## 4. 검증 결과

## 5. 후속 범위 및 주의점
```

## 작성 원칙

- 구현된 사실, 중요한 설계 결정, 실제 실행한 검증 결과를 중심으로 작성한다.
- 테스트·lint·type check 결과에는 실행 명령과 결과를 함께 남긴다.
- 미구현 항목은 `후속 범위`에 기록하고 완료된 것처럼 표현하지 않는다.
- API, migration, 환경 변수 변경은 반드시 기록한다.
- API 키, 비밀번호, production URL, 사용자 원문과 전체 snapshot은 기록하지 않는다.
- 문서 제목과 본문에서 `handoff` 또는 `인수인계` 대신 `개발 기록`을 사용한다.

새 기록을 추가하거나 기존 기록을 이동하면 `docs/archive/README.md`의 개발 기록 목록도 함께 갱신한다.
